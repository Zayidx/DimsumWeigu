## Required workflow order

1. Login, rotate session, resolve permitted outlet and warehouse.
2. Open a shift for that outlet/warehouse before POS mutation.
3. Build and hold server-side cart; revalidate on resume and checkout.
4. Checkout under a database transaction, locking stock, recording payment state and idempotency key.
5. Print only completed/eligible receipts; settle pending gateway payments through verified, idempotent callbacks.
6. Close the shift with calculated expected cash, actual cash, discrepancy, movements and audit record.

Purchasing, transfers, opname, returns and production each use explicit status transitions and write stock/finance ledgers atomically. These transition details come from `Instruction.json`; inspect the corresponding source feature docs and source tests before claiming parity.

## Operational commands

Expense and waste workflows are documented in [operating-costs.md](operating-costs.md); mobile POS endpoints and checkout replay rules in [mobile-pos-api.md](mobile-pos-api.md). The latest `php artisan test` run passed **66 tests / 431 assertions** on SQLite. MySQL concurrency, live providers, hardware and responsive browser QA remain unverified. This is progress evidence, not a declaration that the complete functional scope is finished.

Supplier-return workflows and settlement semantics are documented in [supplier-returns.md](supplier-returns.md). Tests cover the Livewire workflow, idempotency, exact batches, rollback and cross-outlet failures. AdminReportsTest verifies admin/report pages, protected role payloads, conversion bounds, stock export cost/scoping and absence of credential input flashing.

- `php artisan inventory:reconcile` reports differences between global product stock and the sum of warehouse balances. Add `--fix` only when the operator intends to repair the derived aggregate; the command locks the product and recalculates from warehouse balances.
- `php artisan outlet:audit --strict` checks central warehouse rules, saleable outlet warehouses, and active users' single default outlet assignment.
- Scheduler currently runs overdue receivable/payable notifications at 01:15 and low-stock notifications at 02:00. Configure Laravel scheduler to run every minute in deployment.
